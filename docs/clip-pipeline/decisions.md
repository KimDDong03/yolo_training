## 이 목록의 성격

CCTV 프로그램(클립 생성)·부대→서버 전송 체계(업로드 플랫폼)·학습 플랫폼(수신·학습·배포)은
**모두 우리 과가 개발**한다 — 네트워크 회선과 서버 하드웨어만 외부에서 구축·도입된다.
따라서 시스템 간 기술 규격과 전송 구현은 요청 대상이 아니다(문서 하단 "내부 확정 사항").

여기 적힌 것은 **우리가 정할 수 없는 것들** — ① 데이터 규격(파일명·구분 기준 등)의
표준 확정·승인, ② 검수 같은 운영 인력·협조, ③ 보존·파기 같은 데이터 정책, ④ 인프라
도입 일정 확인이다. 데이터과에 요청한다:

- 각 항목을 **결정하거나, 해당 판단의 담당 부서를 지정·전달**해 주기 바란다.
- 회신은 각 항목의 **응답 란**에 결정 내용·담당·일자를 기입하는 방식이면 된다.
- 권고안이 있는 항목은 권고안 수용 시 "권고안대로" 한 줄이면 충분하다.

## D-01. 클립 전달 규격의 데이터 표준 확정·승인

**요청** (전송 체계 자체는 우리 과가 개발한다 — 여기서 구하는 것은 **데이터 표준으로서의
확정·승인**이다):

1. [부록 A 전달 규격서](interface-spec.md)의 **파일명 체계·메타데이터 필드·구분 기준**
   (부대 코드·카메라 ID·이벤트 코드 체계)을 데이터 표준으로 **확정·승인**해 달라.
   이 규격이 이후 모든 수집 데이터의 이름과 분류의 기준이 된다.
2. 데이터과가 **별도로 요구하는 명명·분류·관리 표준이 있으면 제시**해 달라 — 우리 규격에
   반영한다(예: 데이터관리포탈의 등록 명명 규칙과 맞춰야 하는 부분).
3. 배치 주기 확인 — 물리 반출(외장하드) 기반 **월 1회**로 알고 있다. 맞는지, 주기 변경
   계획이 있는지 확인해 달라.
4. **보유 데이터 현황 보고** — 학습 시스템이 보유하게 되는 데이터(이미지·메타데이터)의
   현황을 데이터과에 정기 보고할 필요가 있으면 형식·주기를 알려 달라. 시스템 DB 에서
   부대·기간·상태별 현황을 자동 생성해 제공할 수 있다.

**배경**: 본문 4.1(전송·수신), 7절(명명·코드 대장), 부록 A 전체. 학습 시스템 내부 DB 의
구축(엔진·스키마)은 우리 과 구현 사항이며, 데이터과 표준이 있으면 위 2번 응답으로 접수해
필드 명명·분류에 반영한다.

## D-02. 배치 운영 절차 — 반출입·재전송·준수율 리포트 회람

**요청**:

1. **외장하드 반출입 절차** 확인 — CCTV 감시망(분리망)에서 클립을 외장하드로 반출해

## D-03. 검수 담당 인력 지정

**요청**: 오토라벨 결과를 확인·수정하는 **검수 담당자(들)를 지정**해 달라 — 소속·인원·
1일 가용 시간. 우리 과 단독 수행인지, 데이터과 또는 다른 부서 인력이 참여하는지의 결정.

**근거 수치** (본문 9.3): 월 유입을 전수 검수하면 약 293시간(상근 3명 상당)이라 비현실적.
**권고안 = 2명 × 1일 5시간** 이면 미탐 확인 전량 + 애매 케이스의 절반을 소화하는 예산제
운영이 가능하다. 1명이면 미탐 확인 위주로 축소 운영(모델 개선 속도 저하), 3명이면 보류
적체 해소.

전제: 검수 도구는 웹 화면(교육 부담 낮음). 다중 검수자는 서버 이행(D-08) 후 가능하고,
그 전에는 학습 PC 1대에서 1명씩.

## D-04. 부대별 골든셋 구축 인력·일정

**요청**: 배포 합부 판정 전용 평가셋(골든셋)을 **부대마다** 만들어야 한다 — 부대당
500~1,000장을 사람이 전수 라벨(오토라벨 미사용). 초기 3개 부대 기준 **약 5~10인일**의
집중 작업 담당과 일정을 지정해 달라. (검수 담당(D-03)과 같은 인력이어도 되고, 시점은
파이프라인 가동 전이 이상적)

**배경**: 오토라벨을 거친 평가셋은 모델의 미탐 편향을 공유하므로 배포 판정 기준이 될 수
없다(본문 4.5). 신규 부대 추가 시에도 온보딩 단계로 반복된다(본문 5.5).

## D-05. 데이터관리포탈 이관 방식, 프레임 보존·파기 절차

**확정된 방침**: 원본 클립은 추출 후 **데이터관리포탈**로 이관하고 학습 시스템에서는
삭제한다 — 우리 저장소는 이미지와 메타데이터만 보관한다(본문 6.4). 이를 전제로:

**요청** (보안·기록물 규정 판단이 필요하면 해당 부서로 전달 요망):

1. **포탈 이관 방식** — 전송 경로(API/공유폴더)·계정·용량(연 약 2.3TB 유입), 이관 시
   무결성 확인(해시 대조) 지원 여부.
2. **포탈에서의 재수령(다운로드) 가능 여부** — 추출 간격을 바꿔 재추출할 일이 생기면
   포탈에서 해당 클립을 다시 받아와야 한다(본문 4.2). 불가하면 재추출은 포기 항목이 된다.
3. 포탈에서의 클립 **보존 연한**(포탈 정책 확인).
4. 추출된 **프레임 이미지의 보존 연한과 파기 절차** — 우리 저장소에 남는 것은 이미지다.
   월 폴더 단위 파기가 가능하도록 설계돼 있다. 학습에 편입된 이미지(데이터셋 버전이
   참조)의 취급 포함.
5. 격리 클립(규격 미준수)의 처리 — 종결 후 포탈 이관인지 삭제인지.

## D-06. 얼굴·번호판 마스킹 요구 여부

**참고할 상충 관계**: 마스킹은 탐지 학습 품질과 직접 상충한다 — 특히 "사람" 클래스의

## D-07. 학습 클래스 세분 목록 협의·확정

**요청** (운용 부서·부대 협의가 필요하면 전달 요망): 탐지 클래스는 **2계층**으로 간다
(본문 7.3) — **표출(운용) 클래스는 `사람 / 차량 / 동물`(+해안: 튜브/보트)로 확정**이고
(CCTV 화면·이벤트 표시는 지금과 동일), 모델이 잘 배우도록 **학습 클래스만 그 아래에서
세분**한다. 확정이 필요한 것은 이 세분 목록이다:

1. **실제 출현 객체 목록** — 각 부대에서 실제로 찍히는 동물(멧돼지·고라니·조류 등)과
   차량 종류(전차·장갑차 등 군용 포함)를 알려 달라.
2. **운용상 구분이 필요한 객체** — 표출은 "차량"으로 묶이지만, 통계·분석에서 따로 보고
   싶은 구분(예: 군용/일반)이 있으면 알려 달라 — 학습 클래스에 반영하면 추가 비용 없이
   구분 통계가 나온다.
3. 우리 초안(본문 7.3 표): 차량 → 일반/군용/미상, 동물 → 멧돼지/고라니/조류/기타.
   가감 의견을 달라.

**세분의 기준** (우리가 제시): 화면에서 **판정 가능**해야 하고(야간·원거리에서 사람이
구분 못 하는 세분은 라벨 품질만 해침), 운용·학습상 의미가 있어야 한다. 구분 불가 프레임을
위한 "-미상" 클래스는 구조에 포함돼 있다.

**시급성**: 이 목록이 확정돼야 기존 5만 장 정리(P-B)의 라벨 작업을 시작할 수 있다 —
나중에 바꾸면 그만큼 재라벨이다.

## D-08. 서버 도입 시점·GPU 할당·운영 주체·인증 방식

**요청** (인프라 구축 주체가 데이터과가 아니면 해당 부서로 전달하거나 창구를 지정해 주기
바란다): 도입 예정 GPU 서버·네트워크에 대해 다음을 확정·공유해 달라. (**GPU H200 × 16장,
스토리지 21TB 는 확정**으로 확인됐고 산정 수요를 크게 상회한다 — 본문 9.2. 서버 내부
구성과 그 위의 소프트웨어는 전부 우리 과가 설계·개발한다.)

1. **도입 시점**과, 서버가 공용이라면 **학습 플랫폼에 할당되는 GPU 수·스케줄 정책** —
   이 파이프라인의 상시 수요는 월 배치 처리 수 시간 + 학습이라 1~2장으로도 충분하다
   (할당이 늘면 다중 GPU 학습으로 그대로 활용). 드라이버는 **550 이상**(CUDA 12.8 계열)
   설치를 확인해 달라. (서버 내부의 소프트웨어 구성 — DB 포함 — 은 우리 과가 설계·구축
   한다. 별도 협의 불요)
2. **업로드 지점 환경** — 업로드 지점(외장하드를 꽂고 올리는 곳)의 위치·PC·서버망 연결
   대역. 월 1회 약 190GB(3부대 합) 일괄 업로드 전제 — 유선 LAN 이면 수 시간 수준.
3. Kubernetes 구성·운영 주체(장애·업데이트 대응 창구).

## D-12. 배포 합부 기준 수치 승인

**요청**: 새 모델의 배포 가부를 판정하는 기준(본문 4.7의 구조)의 **수치**를 협의·승인해

승인 주체가 필요하다.

1. 필수 클래스 목록과 클래스별 최저선(예: 사람 재현율 ≥ 0.9)

   보류(부대별 배포 가능, 본문 5.3)
