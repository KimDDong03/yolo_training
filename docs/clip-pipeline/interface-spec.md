# 부록 A — 클립 전달 인터페이스 규격서

| | |
|---|---|
| 문서 상태 | 초안 v1 (2026-08-27) — 확정 요청용 |
| 수신 | **데이터과** — 파일명·구분 기준 등 데이터 표준의 확정·승인 요청([D-01](decisions.md#d-01)) |
| 규격 버전 | `schema_version: 1` |
| 상위 문서 | [기획서 본문](README.md) (특히 4.1 수신·검증, 7 명명 규칙) |

이 문서는 부대 CCTV 프로그램이 생성한 클립을 학습 시스템에 전달할 때의 **파일·메타데이터
규격**이다. 송신(CCTV 프로그램)·전송(업로드 모듈)·수신(학습 플랫폼) 구현은 모두 우리 과가
담당하므로 기술 협상 문서가 아니라, **이후 모든 수집 데이터의 이름·분류 기준이 될 데이터
표준을 확정·승인받기 위한 근거 문서**다. 송신측 구현이 이 문서만으로 가능한 수준으로
자기완결적으로 작성했다(향후 인수인계 대비).

---

## 1. 전달 단위 — 부대 단위 배치

- 한 배치 = **한 부대**의 일정 기간(기본 30일) 클립 전체. 여러 부대를 한 배치에 섞지 않는다.
- 배치는 폴더 하나로 전달한다:

```
U003-202608-01/                      ← 배치 폴더 (배치 ID 와 동일)
├── manifest.json                    ← 배치 매니페스트 (필수, 1개)
├── U003_CAM01_20260801T063012_PERSON_0001.mp4
├── U003_CAM01_20260801T063012_PERSON_0001.json   ← 클립별 사이드카 (필수)
├── U003_CAM01_20260801T091500_ANIMAL_0002.mp4
├── U003_CAM01_20260801T091500_ANIMAL_0002.json
└── ... (클립 + 사이드카 쌍의 나열, 하위 폴더 없음)
```

- **배치 ID** = `{부대코드}-{YYYYMM}-{일련2자리}` (예: `U003-202608-01`).
  같은 달에 재전송·분할 전송이 생기면 일련번호를 올린다.
- 실제 이동은 **CCTV 감시망(분리망)에서 외장하드로 반출 → 업로드 지점에서 업로드 도구로
  일괄 업로드**하는 월 1회 방식이다(본문 4.1 — 내보내기·업로드 도구 모두 우리 과 개발).
  이 규격의 배치 폴더 구조는 ① CCTV 프로그램의 "배치 내보내기"가 외장하드에 만드는
  구조이자 ② 업로드가 완성하는 서버측 최종 상태다 — 이동 방식이 바뀌어도 이 구조는
  불변이다.

## 2. 클립 파일명 규격

```
{부대코드}_{카메라ID}_{YYYYMMDD}T{HHMMSS}_{이벤트코드}_{일련4자리}.mp4
예: U003_CAM07_20260801T221304_PERSON_0012.mp4
```

| 필드 | 형식 | 규칙 |
|---|---|---|
| 부대코드 | `U` + 숫자 3자리 | 학습 시스템 측이 발급·관리(코드 대장). 임의 생성 금지 |
| 카메라ID | `CAM` + 숫자 2~3자리 | 부대 내에서 유일. 카메라 교체 시 새 번호 발급 |
| 일시 | `YYYYMMDD` + `T` + `HHMMSS` | **이벤트 탐지(트리거) 시각, KST(한국표준시)** — 클립 시작 시각이 아님(시작 = 트리거 − pre). 정본 시각은 사이드카(3절)의 시간대 포함 값 |
| 이벤트코드 | 대문자 영문 2~12자 | 8절 이벤트 코드 사전의 값만 사용. **동시 감지 시 주 트리거 하나만 표기** — 주 트리거 = 최초 감지 이벤트, 완전 동시면 사람>차량>동물 우선. 감지 전체 목록은 사이드카 `event_types` |
| 일련 | 숫자 4자리 | 같은 카메라·같은 초에 클립이 2개 이상일 때 구분. 배치 내에서 카메라별 증가 |

- 문자 집합: 필드 값은 **ASCII 대문자·숫자만**, 구분자는 밑줄, **확장자는 소문자
  `.mp4`**. 한글·공백·특수문자 금지(전송·저장 경로의 인코딩 사고 방지).
- 검증 정규식 (수신측이 이것으로 검사한다):

```
^U[0-9]{3}_CAM[0-9]{2,3}_[0-9]{8}T[0-9]{6}_[A-Z]{2,12}_[0-9]{4}\.mp4$
```

- 사이드카 파일명 = 클립 파일명에서 확장자만 `.json` 으로 바꾼 것.

## 3. 클립별 사이드카 JSON

클립 1개마다 같은 이름의 `.json` 파일을 반드시 동봉한다. **메타데이터의 정본은 사이드카**
이고 파일명은 사람이 읽기 위한 중복 표기다(불일치 시 격리 후 회신).

> 구현 참고 (레포 실사): 프로그램에는 이미 클립 매니페스트·사이드카 체계(`ClipManifest`
> — 트랙 ID·클래스·신뢰도·정규화 bbox·모델 참조 포함)가 있다. 이 규격은 신규 발명이
> 아니라 **그 체계를 아래 필드로 확장·정렬하는 것**이다(부록 B I-01). 내부 시각이
> epoch 밀리초이므로 사이드카 기록 시 ISO 8601 변환은 송신측 구현 사항이다.

### 3.1 필드 정의

| 필드 | 타입 | 필수 | 예 | 설명 |
|---|---|---|---|---|
| `schema_version` | 정수 | 필수 | `1` | 이 규격의 버전. 필드 추가 시에만 증가 |
| `unit_id` | 문자열 | 필수 | `"U003"` | 부대 코드 (파일명과 일치해야 함) |
| `unit_type` | 문자열 | 필수 | `"coastal"` | 부대 유형: `inland`(내륙) / `coastal`(해안) — 클래스 프로파일 결정에 사용 |
| `camera_id` | 문자열 | 필수 | `"CAM07"` | 카메라 ID (파일명과 일치) |
| `event_ts` | 문자열 | 필수 | `"2026-08-01T22:13:04+09:00"` | **이벤트 탐지(트리거) 시각** — 클립 시작 시각이 아니다. 클립 시작 = event_ts − pre_ms. **ISO 8601, 시간대 오프셋 필수** |
| `event_type` | 문자열 | 필수 | `"PERSON"` | **주 트리거** 이벤트 코드 (8절 사전 값, 파일명과 일치) |
| `event_types` | 문자열 배열 | 선택 | `["PERSON","VEHICLE"]` | **동시 감지된 이벤트 전체** (주 트리거 포함). 사람·차량이 함께 감지돼도 클립은 1개로 내고 이 배열에 기록한다 — 수신측 미탐 판정이 이 집합 전체를 기대 객체로 본다. 없으면 event_type 하나로 간주 |
| `event_score` | 실수 | 필수 | `0.83` | 이벤트 감지 신뢰도 0.0~1.0 (없으면 `null`) |
| `pre_ms` | 정수 | 필수 | `5000` | 트리거 **이전** 녹화 버퍼(밀리초). 기본 5초, **부대별 설정으로 상이 가능** — 수신측의 프레임별 트리거 상대 위치 계산에 필수 |
| `post_ms` | 정수 | 필수 | `10000` | 트리거 **이후** 녹화 길이(밀리초). 기본 10초, 부대별 설정으로 상이 가능 |
| `duration_s` | 실수 | 필수 | `15.0` | 클립 길이(초) ≈ (pre_ms + post_ms) / 1000 |
| `fps` | 실수 | 필수 | `15.0` | 프레임률. **수신측은 파일 헤더가 아니라 이 값을 신뢰**한다 |
| `resolution` | 문자열 | 필수 | `"1920x1080"` | 가로x세로 |
| `codec` | 문자열 | 필수 | `"h264"` | 영상 코덱 (5절 허용 목록) |
| `sha256` | 문자열 | 필수 | `"a3f1...c9"` (64자 hex) | **클립 파일 전체의 SHA-256.** 수신측이 재계산해 대조 |
| `sw_version` | 문자열 | 필수 | `"1.4.2"` | CCTV 프로그램 버전 |
| `model_version` | 문자열 | 필수 | `"m-2026-07-r1"` | **이 이벤트를 감지한 배포 모델의 버전** (배포 매니페스트의 버전 문자열). 미상이면 `"unknown"` |
| `incident_id` | 문자열 | 선택 | `"INC-20260801-0042"` | 사건 상관 ID — 객체가 지속돼 **이어서 생성된 연속 클립들**이 한 사건임을 표시(같은 값 유지). CCTV 프로그램이 직접 발급한다(우리 과 구현, 부록 B I-01). 수신측이 연속 클립 간 시간 겹침 중복 제거·추적 단절 판정에 사용. 구버전 클립에는 없을 수 있어 '선택'이며, 없으면 수신측이 시간 간격 규칙으로 대체 판정 |

- 위에 없는 필드가 와도 무시한다(전방 호환). 필수 필드가 빠지면 그 클립은 격리된다.
- `model_version` 을 요구하는 이유: 다음 세대 모델 학습 시 "어느 모델이 놓친 장면인가"를
  추적해 모델 개선 효과를 세대별로 측정한다.

### 3.2 사이드카 전체 예시

```json
{
  "schema_version": 1,
  "unit_id": "U003",
  "unit_type": "coastal",
  "camera_id": "CAM07",
  "event_ts": "2026-08-01T22:13:04+09:00",
  "event_type": "PERSON",
  "event_types": ["PERSON", "VEHICLE"],
  "event_score": 0.83,
  "pre_ms": 5000,
  "post_ms": 10000,
  "duration_s": 15.0,
  "fps": 15.0,
  "resolution": "1920x1080",
  "codec": "h264",
  "sha256": "a3f1e08c5d2b9a7f4e6c1d0b8a9f3e2d5c4b7a6f9e8d1c0b3a2f5e4d7c6b9a0c",
  "sw_version": "1.4.2",
  "model_version": "m-2026-07-r1",
  "incident_id": "INC-20260801-0042"
}
```

- 인코딩: **UTF-8 (BOM 없음)**.

## 4. 배치 매니페스트 (manifest.json)

배치의 완결성(빠진 파일 없음)과 무결성(파일 변조·손상 없음)을 검증하는 정본. 배치 폴더
최상단에 1개.

```json
{
  "schema_version": 1,
  "batch_id": "U003-202608-01",
  "unit_id": "U003",
  "period": { "from": "2026-08-01", "to": "2026-08-30" },
  "created_at": "2026-08-31T06:00:00+09:00",
  "clip_count": 8993,
  "clips": [
    {
      "file": "U003_CAM01_20260801T063012_PERSON_0001.mp4",
      "size": 7340032,
      "sha256": "a3f1...c9"
    }
  ]
}
```

| 규칙 | 내용 |
|---|---|
| `clip_count` | `clips` 배열 길이와 일치해야 한다 |
| `clips[].sha256` | 각 클립 사이드카의 `sha256` 과 일치해야 한다 |
| 사이드카 파일 | 매니페스트에 나열하지 않는다(클립과 1:1 쌍 규칙으로 검증) |
| 수신측 검증 | 목록 대 실파일 대조 → 누락분은 **재전송 요청 목록**으로 회신, 있는 것부터 처리(배치 전체를 막지 않음) |

## 5. 영상 규격

| 항목 | 요구 | 비고 |
|---|---|---|
| 컨테이너 | **MP4** | 프로그램이 이미 MP4 아티팩트 2종(미리보기/증거용)을 생성한다 — **학습 전달본은 증거용(EVIDENCE, 원본 화질)** 을 쓴다. 벤더 전용 포맷 불가 |
| 코덱 | **H.264 (AVC)** | 현행 인코더(GStreamer 경로) 출력 코덱은 미확인 — H.264 설정 확인이 송신측 구현 항목(I-01). H.265 는 시범 검증 후 허용 여부 결정 |
| 해상도 | **최소 640 이상 보장** — 카메라별로 상이함을 허용 | 원본 해상도 유지, 축소·업스케일 재인코딩 금지 — 원거리 소형 객체 학습에 필요 |
| 길이 | pre_ms + post_ms (기본 5초+10초 = 15초, 부대별 설정 상이 가능) | 사이드카의 pre/post 값과 실제 길이가 크게 어긋나면 회신에 표기 |
| 시각 동기 | **감시망 내 NTP 동기화, 불가 시 주기적 시각 점검** (분리망이라 외부 NTP 접근이 없을 수 있음) | `event_ts` 가 사건 그룹 묶기·통계의 기준. 미래 시각·큰 편차는 격리 사유 |

## 6. 무결성 · 중복 · 재전송 규칙

- **무결성**: 수신측은 모든 클립의 SHA-256 을 재계산해 사이드카·매니페스트와 대조한다.
- **클립 정체성** = (unit_id, camera_id, event_ts, sha256).
  - 동일 정체성 + 동일 해시가 다시 오면: **조용히 건너뛴다**(중복 수신 무해 — 재전송은
    언제나 안전하다).
  - 동일 정체성 + 다른 해시: 둘 다 보존하고 충돌로 표시, 회신에 포함.
- **재전송**: 누락·격리분 재전송은 새 배치 ID(일련 증가)로 보낸다. 이미 정상 수신된
  클립이 섞여 있어도 무방하다(위 멱등 규칙).

## 7. 격리(quarantine)와 준수율 회신

규격을 어긴 클립은 버리지 않고 **격리 보관 + 사유 기록 + 배치별 회신**한다.

### 7.1 격리 사유 코드

| 코드 | 사유 |
|---|---|
| `NO_SIDECAR` | 사이드카 없음 |
| `BAD_FILENAME` | 파일명 규격 위반 (자동 명명 후 격리 보관) |
| `HASH_MISMATCH` | SHA-256 불일치 (사이드카·매니페스트 대비) |
| `MISSING_FIELD` | 사이드카 필수 필드 누락·형식 오류 |
| `NAME_META_CONFLICT` | 파일명과 사이드카 내용 불일치 (이벤트는 `event_type` 단수 필드와만 대조 — `event_types` 배열과는 비교하지 않음) |
| `BAD_TIMESTAMP` | 시각 이상(미래 시각, 기간 밖, 시간대 없음) |
| `DECODE_FAIL` | 영상 열기·디코딩 실패 |
| `BAD_FORMAT` | 허용 외 컨테이너·코덱 |
| `IDENTITY_CONFLICT` | 동일 정체성·다른 해시 충돌 |

### 7.2 준수율 회신 리포트

배치 처리 후 학습 시스템이 자동 생성한다. 격리 원인의 상당수는 부대 현장 장비 상태(시계
미동기, 구버전 프로그램, 손상 파일)이므로, 부대 장비 점검 계통과 프로그램 업데이트 판단에
쓰이도록 회람한다(경로는 [D-02](decisions.md#d-02)):

```
배치 U003-202608-01 수신 결과
  수신 8,993 / 정상 8,940 (99.4%) / 격리 53
  격리 내역: NO_SIDECAR 41, HASH_MISMATCH 7, DECODE_FAIL 5
  재전송 요청: 매니페스트 대비 누락 7건 (목록 별첨)
```

## 8. 이벤트 코드 사전 (확정안 — 운용 이견 확인은 D-07 연계)

**레포 실사 결과** (AI_CCTV_FINAL_VER1, `PublishClassMapping.h`): 프로그램은 COCO 80
클래스를 **person / animal(bird·cat·dog 만 허용) / vehicle(car·bus·truck·motorcycle)**
3종으로 정규화해 발행한다. 이벤트 코드는 이 발행 클래스와 1:1 로 정렬한다 — 학습 시스템의
미탐 판정(이벤트는 났는데 해당 객체 미검출 → 검수 우선)이 이 대응에 의존한다.

| 코드 | 의미 (프로그램 내부 식별자) | 기대 객체(전역 클래스) |
|---|---|---|
| `PERSON` | 사람 감지 (`person`) | 사람 |
| `VEHICLE` | 차량 감지 (`vehicle` = car·bus·truck·motorcycle) | 차량 |
| `ANIMAL` | 동물 감지 (`animal` = bird·cat·dog) | 동물 |
| `BOAT` | 선박·부유체 감지 (해안 부대 편입 시 매핑 추가 — COCO `boat` 활용 가능) | 보트, 튜브 |
| `MISS_REPORT` | **미탐 신고** — 모델이 경보하지 않은 상황을 운용자가 수동 저장 | 신고 대상 객체 — 수신측이 최우선 검수 |
| `FP_REPORT` | **오탐 확정** — 이벤트 경보를 운용자가 오경보로 기각 | (기대 객체 없음) — 수신측이 하드 네거티브로 활용 |
| `MANUAL` | 운용자 수동 저장 (위 두 경우가 아닌 일반 저장) | (기대 객체 없음) |
| `OTHER` | 기타 | (기대 객체 없음) |

## 9. 규격의 변경 관리

- 필드 **추가**는 `schema_version` 증가로 한다. 수신측은 모르는 필드를 무시하므로 송신측이
  먼저 올려도 안전하다.
- 필드의 의미 변경·삭제는 하지 않는다(새 필드 추가로 대체).
- 이벤트 코드·부대 코드·카메라 ID 의 추가는 규격 버전과 무관하게 코드 대장 갱신으로
  한다(발급·관리 주체: 우리 과 — 본문 7.2).

## 10. 송신측 체크리스트 (요약)

- [ ] 배치 폴더명 = 배치 ID, 한 부대만 포함
- [ ] 모든 클립에 같은 이름의 사이드카 JSON (UTF-8, 필수 필드 완비)
- [ ] manifest.json 에 전 클립의 파일명·크기·SHA-256
- [ ] 파일명 규격·정규식 통과 (ASCII, KST, 이벤트 코드는 사전 값)
- [ ] MP4 + H.264, 원본 해상도(최소 640), 길이 = pre_ms + post_ms 와 일치
- [ ] 장비 NTP 동기화, event_ts 에 시간대 오프셋
- [ ] 재전송 시 새 배치 ID (중복 포함 무방)
